# テック朝刊

毎朝 **07:00（Asia/Tokyo / 日本時間）** に、前日07:00〜当日07:00のテックニュースを調査し、日本語のMarkdownをPull Requestで届けます。

## 配信方式

このリポジトリに接続した **Codexの定期タスク** がWeb調査とGitHubへの投稿を実行します。スケジュール本体はCodex側で管理します。このリポジトリだけをcloneしても定期実行は始まりません。GitHub Actionsや追加のAPIキーは使用しません。

- 実行開始: 毎日07:00 JST。PRの到着は調査・生成が完了した後です。
- 保存先: `news/YYYY/MM/YYYY-MM-DD.md`
- ブランチ: `news/YYYY-MM-DD`
- PRタイトル: `テック朝刊 YYYY-MM-DD`
- マージ先: 実行時のデフォルトブランチ。マージは読者が行います。
- 再実行: 同日の完成済み・マージ済み・閉じられたPRは再作成しません。途中失敗だけ再開します。

## 編集方針

AI、開発・OSS、クラウド、半導体・ハードウェア、セキュリティ、日本のテック動向から重要度順に5〜10件を目安に選びます。確認できる件数が少ない日は水増ししません。

各号には対象期間と生成日時、3行の要点、主要ニュース、短報、編集メモを記載します。各ニュースは「何が起きたか」「なぜ重要か」「公開・発表日時」「出典リンク」で構成します。全体1500〜3000字程度を目安にします。

一次情報を優先し、ページを開いて事実と日時を確認します。検索結果の断片だけの記事、期間所属が確認できない記事、噂は掲載しません。事実と考察を区別し、同じ出来事や過去の号との重複を取り除きます。重要な続報は新しい点を示して掲載します。長文の転載はしません。

## 運用

Codexの定期タスク「テック朝刊をPRで配信」で時刻や編集方針を変更・一時停止できます。ローカルの定期実行を利用するため、実行時にPCとCodexアプリを起動し、インターネット接続とGitHub連携を維持してください。定刻の配信完了を保証する仕組みではありません。

検索・接続・投稿の失敗は「ニュースなし」と区別して報告します。ニュースがない旨の号は、調査が正常に完了した場合だけ作ります。日付をまたいだ停止期間の号は自動で埋めず、必要に応じて再作成を指示してください。

GitHubで通知を受け取るには、このリポジトリのWatch設定でPull requestsを購読してください。Codexのタスクにも作成したPRのリンクが残ります。

初期設定時には編集方針と定期実行を登録します。最初のニュース号は次の定期実行で作成します。
